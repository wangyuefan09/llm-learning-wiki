## 核心执行链路

### 会话入口

`AgentContext.communicate()` 负责接收消息。上下文空闲时启动 `_process_chain()`；上下文正在执行时，把新消息设置为 intervention。`_process_chain()` 将用户消息写入当前 Agent History，调用 `monologue()`，如果当前 Agent 是子 Agent，再把返回结果递归交回上级。

### Agent Loop

`Agent.monologue()` 的内层 `while True` 是主要执行循环：

1. 调用 message loop 扩展；
2. `prepare_prompt()` 组装上下文；
3. `call_chat_model_turn()` 调用主模型；
4. 记录模型回复；
5. `process_llm_result_tools()` 处理原生 function call 或回退到 JSON 工具解析；
6. `_execute_tool_request()` 执行工具；
7. 工具 `after_execution()` 把结果写回 History；
8. 工具未结束循环时进入下一轮。

### 上下文压缩

`History` 维护 `current`、`topics` 与 `bulks`：

- 当前消息集中在 current topic；
- 子任务结束等场景可以建立 new topic；
- 超限时先处理超长消息，再摘要 topic；
- 较早 topics 合并成 bulk，bulks 继续合并；
- 上下文仍超限且无法压缩时，最早 bulk 可能被移除。

### 多Agent

`Delegation.execute()` 创建或复用 subordinate，设置 `SUPERIOR/SUBORDINATE` 引用，写入子任务并调用子 Agent `monologue()`。返回后 `new_topic()` 封存子 Agent 当前主题，结果作为主 Agent 的工具结果。

`helpers.parallel_tools` 额外创建并行 job。子 Agent job 使用独立 Worker Context，并复制父 Context 的 Project 绑定；直接工具 job 在工作上下文执行。系统提供完成、取消和清理逻辑，并阻止并行 worker 递归创建并行任务。

### Memory与Project

Memory 根据当前 Agent 所属 Project 计算存储子目录。启用默认项目隔离时，索引位于：

```text
usr/projects/<project>/.a0proj/memory
```

Project 知识位于：

```text
usr/projects/<project>/.a0proj/knowledge
```

项目主指令与附加指令进入 Prompt，文件树作为每轮 Extras，variables、secrets、MCP、Skills 和子 Agent 开关由项目元数据管理。
