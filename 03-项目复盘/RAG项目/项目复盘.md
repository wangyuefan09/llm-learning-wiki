# RAG项目复盘

## 一句话介绍

这是我独立设计并实现的风电领域本地知识库项目，面向风电设备、风场运维、故障诊断、检修 SOP、告警处理和技术资料。系统只接收人工上传的 PDF、DOCX、Markdown 和 TXT 文档，完成结构化解析、章节感知切分、表格检索、Embedding、OpenSearch 混合检索、普通 RAG、流式 RAG、七节点 Agentic RAG 和 Langfuse 观测。

项目已经完成风电领域核心链路的设计与实现。介绍项目时仍要区分：源码已经实现的工程能力、自动化测试验证结果，以及尚未用真实风电数据证明的效果结论。

## 项目背景与目标

- GitHub：[wangyuefan09/agentic-rag](https://github.com/wangyuefan09/agentic-rag)
- 项目负责人：个人独立设计与实现
- 业务目标：把分散在 PDF、DOCX、Markdown 和 TXT 中的风电技术资料组织成可检索、可追溯的知识库，为设备运维和故障诊断问答提供证据
- 数据入口：人工上传风电文档，不引入与核心业务无关的自动采集流程
- 查询入口：FastAPI、SSE 流式接口和 Gradio

- 接入 Langfuse，并补充静态检查、单元测试和覆盖率门禁。

## 系统架构

### 文档摄取

```text
人工上传风电文档
→ 文件类型、大小与文件内容校验
→ SHA-256 内容哈希与数据库唯一约束去重
→ Docling 或轻量解析器
→ sections、raw_text、tables、metadata
→ section-aware 文本切分 + 表格语义切分
→ Embedding
→ OpenSearch staging 切片
→ 校验后切换为 ready
```

PostgreSQL 保存文档状态、业务元数据、处理租约和表格原始结构；OpenSearch 保存文本/表格切片、检索字段和向量。

### 普通RAG查询

```text
FastAPI 请求
→ 公开访问上下文与 metadata 过滤
→ query embedding，失败时回退 BM25
→ OpenSearch BM25 + HNSW
→ RRF 融合
→ Prompt 构造
→ LLM 生成
→ 返回答案与来源
```

流式问答使用同一检索准备逻辑，通过 SSE 返回来源和生成片段。OpenSearch 基础设施异常在首个流事件前返回 503，正常零结果与基础设施失败分开处理。

### Agentic RAG查询

```text
guardrail
├─ 超范围 → out_of_scope → 结束
└─ 风电问题 → retrieve → tool_retrieve → grade_documents
                                  ├─ 有相关证据 → generate_answer
                                  └─ 无相关证据 → rewrite_query → retrieve
```

默认最多检索两次。达到上限后，系统提示补充设备型号、部件、故障码、故障现象、运行工况和时间范围。

## 已实现的关键能力

### 文档解析与表格

- PDF、DOCX 使用 Docling；Markdown、TXT 使用轻量解析器。
- 统一输出 `sections`、`raw_text`、`tables`、`figures`、`metadata`。
- PDF 支持可配置 OCR、表格结构识别和双栏阅读顺序后处理。
- Markdown 可以按标题生成 section，并提取 Markdown 表格。
- 表格原始 `rows`、Markdown 和 HTML 按文档版本保存到 `document_tables`。
- `TableChunker` 将表题、表头和行值转换为 `chunk_type=table` 的语义文本，参与 BM25 和向量检索；命中后可按 `doc_id + version + table_id` 回查原始结构。

### 文本切分

- 优先使用 section 作为语义边界。
- 合并过短 section，对过长 section 递归拆分。
- section 不可用时回退到 `raw_text`。
- 使用中文字符/标点、英文词和其他字符的启发式方法估算长度。
- 默认 `chunk_size=800`、`overlap_size=100`、`min_chunk_size=120`，并设置 `max_chunk_chars=6000` 硬上限。
- 当前只实现 LangChain `RecursiveCharacterTextSplitter` 这一套底层切分策略。

### 索引与检索

- OpenSearch Mapping 使用严格字段和 schema version 校验。
- 正文、标题、章节使用 CJK analyzer。
- 故障码、风机型号、部件等字段使用 `keyword`。
- HNSW 负责向量召回，RRF 负责融合 BM25 和向量排名。
- 支持 `kb_id`、文档类型、风场、风机型号、部件和故障码过滤。
- Mapping 不兼容时启动失败并提示重建，不自动删除已有索引。

### 文档状态与恢复

- `(kb_id, content_hash)` 唯一约束保证并发去重。
- 文档状态包括 `pending`、`processing`、`ready`、`failed`、`deleting`、`deleted`。
- 入库、重新索引和删除使用 token、租约与数据库 CAS，旧任务不能覆盖新接管者。
- reindex 采用 staging、数量校验、版本切换和补偿回滚，不宣称 PostgreSQL 与 OpenSearch 之间具有严格分布式事务。
- 删除先把切片下线，再更新数据库状态和物理清理；进程中断后可以接管过期的 `deleting` 状态继续执行。

### 权限边界

- 所有公开查询入口强制使用公开访问上下文，只召回公开文档。
- 问答和检索请求不接受客户端提交的权限 ID；文档上传元数据可以写入 `permission_ids`，但当前公开问答入口不会把它们视为调用者权限。
- `AccessContext.trusted/admin` 是供未来认证层使用的内部能力。
- 当前没有用户认证和完整权限管理接口，因此不能把内部访问上下文说成已完成的多租户认证系统。

### 可观测性

- 普通 RAG 记录请求、Embedding、检索和生成相关观测。
- Agentic RAG 记录请求级 trace 和守卫、检索、评分、改写、生成等节点观测。
- 检索基础设施异常会把检索 span 标记为 `ERROR`。
- `/feedback` 可以按 `trace_id` 写入评分和评论。
- 应用关闭时依次释放 Langfuse、Redis、OpenSearch 和数据库资源。

## 当前默认配置

| 配置 | 当前默认/示例值 | 准确解释 |
| --- | --- | --- |
| 切分策略 | `langchain_recursive` | 当前唯一底层策略 |
| chunk_size | 800 | 启发式长度单位，不是严格模型 Token |
| overlap_size | 100 | 与启发式长度函数使用同一单位 |
| min_chunk_size | 120 | 小 section 合并阈值 |
| max_chunk_chars | 6000 | 字符硬上限 |
| Embedding provider | `openai_compatible` | 模型名称由运行配置提供 |
| 示例向量维度 | 1024 | 必须与实际 Embedding 输出一致 |
| 向量索引 | HNSW | `nmslib`、余弦相似度 |
| HNSW m | 16 | Mapping 配置值 |
| HNSW ef_construction | 512 | Mapping 配置值 |
| 检索融合 | RRF | `rank_constant=60` |
| Agent Top-K | 3 | `GraphConfig` 默认值 |
| 最大检索次数 | 2 | `GraphConfig` 默认值 |
| 处理租约 | 1800 秒 | 入库、reindex 和删除恢复使用 |

## 当前缺口

- 没有用户认证和完整权限管理接口。
- 文档处理仍在上传请求内同步执行，没有后台任务队列、自动任务重试和死信处理；`failed` 文档可以通过重新上传同内容手工触发重试。
- 没有可用的数据库迁移目录，开发模型变化后需要重建数据库。
- 上传文件仍保存在本地磁盘，没有对象存储。
- 没有 Cross-Encoder Reranker。
- 没有网页搜索节点和独立证据不足节点；当前兜底在 `retrieve` 节点内完成。
- 没有 Ragas 或等价的离线评估流水线。
- 没有正式的风电检索评估集、chunk 分布报告、容量数据和压测报告。

详细证据见：[[03-项目复盘/RAG项目/源码核验记录|源码核验记录]]。
