## 需要准确表述的细节

### 长度单位

当前 `chunk_size=800` 使用启发式长度函数：中文字符和标点按单元计数、英文按词计数、其余字符按估算折算。它比单纯空白分词更适合中文，但仍不是目标 Embedding 模型 tokenizer 的严格 Token 数。

准确说法：

> 项目使用中文友好的启发式 Token 估算控制递归切分，并通过 6000 字符硬上限保护极端长文本；后续仍需用实际 Embedding tokenizer 和检索评估集校准参数。

### Embedding模型与维度

项目不绑定某个具体 Embedding 模型。示例配置使用 OpenAI-compatible provider、模型占位符和 1024 维，运行时必须保证 Embedding 输出维度与 OpenSearch Mapping 一致。

准确说法：

> Embedding provider、模型和维度均通过配置注入；当前示例维度为 1024，模型优劣尚未通过风电评估集证明。

### 表格检索

`TableChunker` 会重复文档标题、表题和表头，把行数据展开为 `列名=值` 的语义文本，并记录 `table_id`、`row_start`、`row_end`。原始 rows、Markdown 和 HTML 保存在 PostgreSQL，只有 ready 活动版本可以通过表格接口回查。

准确说法：

> 表格已经实现“语义文本负责召回、原始结构负责回查”，但复杂合并单元格和跨页表格效果仍需真实样本验证。

### 权限

公开问答、检索 API 和 Gradio 使用 `AccessContext.public()`，只能召回没有权限标记的文档。`trusted/admin` 是内部对象，当前没有认证层把真实用户身份映射成可信访问上下文。

准确说法：

> 项目已经实现查询前的权限过滤机制和缓存隔离基础，但尚未完成用户认证、多租户权限管理和管理接口保护。

### reindex与删除一致性

项目通过数据库 CAS、token、租约、OpenSearch 状态和补偿逻辑降低跨系统不一致风险，但 PostgreSQL 与 OpenSearch 之间没有分布式事务。

准确说法：

> 项目实现了可验证版本切换、补偿回滚和崩溃后接管，不宣称严格原子提交。

### Reranker

项目没有独立 Cross-Encoder Reranker。当前链路是 RRF 融合，再由 Agentic RAG 的 LLM 文档评分节点做证据过滤和路由。

准确说法：

> RRF 是排名融合，LLM 评分是 Agent 节点；二者都不等同于已接入专用 Reranker。

## 项目范围核验

当前源码、测试、README 和项目说明均以风电知识库为唯一业务域：数据只通过人工上传进入系统，没有自动采集流程；网页搜索属于未实现能力；项目中不包含与该业务域无关的消息入口。
