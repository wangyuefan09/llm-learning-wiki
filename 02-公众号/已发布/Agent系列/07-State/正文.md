# Agent 的状态是什么？为什么多步骤任务需要 State

> [!info] 发布归档
> 公众号页面、作者和发布时间已核验。本地保留文章入口、内容提要与知识库关联；完整正文、代码排版和图片以[公众号原文](https://mp.weixin.qq.com/s/SiqbQs6ymgDOTJlJSCpDWQ)为准。

Agent 系列第七篇。前六篇依次介绍了 Agent 与普通对话的区别、Agent 的基本组成、Agent Loop、CoT、ReAct 和 Plan-and-Execute、Tool Calling 与 Memory。模型会思考，工具能执行，循环负责推进，Memory 保存跨任务信息。还差一个问题：任务执行到一半，程序怎样记住现场？

## 内容提要

文章把 Agent State 定义为由程序维护的结构化任务现场。它记录任务身份、当前状态和步骤、已完成步骤、业务变量、工具调用、循环与重试次数、确认状态、最后错误和版本号。模型负责提出下一步动作与参数，程序完成校验、执行和状态更新，避免模型直接覆盖整份 State。

文章进一步区分 Context、State 与 Memory：Context 决定本次模型调用能看到什么，State 记录当前任务执行到了哪里，Memory 保存跨任务仍有价值的信息。聊天消息可以属于 State，但流程控制、幂等键、版本号和错误信息需要结构化保存，不能只依赖自然语言历史。

在持久化与恢复方面，文章讨论了 Redis 与数据库、Checkpoint、关键副作用前后的状态落盘，以及大工具结果只在 State 中保存引用和摘要。可靠性部分覆盖版本控制、并发更新、工具幂等、错误分类、事务一致性与敏感信息治理。Agent Loop 每轮都围绕读取 State、构建 Context、执行动作和保存新 State 展开。
