# Agent评估与面试问题清单

## 为什么不能只看最终答案

Agent 可能偶然得到正确结果，但过程包含多次无效调用、错误副作用或不可恢复步骤。也可能中间计划合理，但某个工具失败导致最终任务未完成。因此评估要覆盖任务结果、轨迹、工具、上下文和系统资源。

## 五层评估

### 1. 任务结果

- 端到端成功率；
- 答案或 Artifact 正确性；
- 完整性；
- 约束遵循率；
- 人工验收通过率。

### 2. 规划与轨迹

- 是否选择正确工具；
- 平均步骤数；
- 无效或重复步骤率；
- 错误后恢复率；
- 是否过早结束；
- 子任务拆解与结果合并正确率。

### 3. 工具

- Tool Call Schema 正确率；
- 工具调用成功率；
- 参数修复率；
- 超时与重试率；
- 副作用重复率；
- 取消后资源清理率。

### 4. 上下文与记忆

- 压缩后关键信息保留率；
- Memory Recall@K、Precision@K、MRR；
- 错误Project召回率；
- 陈旧记忆使用率；
- Prompt各区域Token占比；
- Tool结果裁剪后的任务影响。

### 5. 系统

- P50/P95/P99延迟；
- 每任务模型调用数；
- 输入/输出Token与成本；
- 并发任务数；
- WebSocket重连与事件补齐率；
- 快照、回滚和故障恢复率。

## 任务集设计

按工具和复杂度分层：

| 类型 | 示例 | 主要验证 |
| --- | --- | --- |
| 单工具 | 读取文件并回答 | Schema、结果回填 |
| 多工具串行 | 查网页后生成文档 | 状态传递、步骤顺序 |
| 有状态Browser | 登录后填写多页表单 | Runtime、页面恢复 |
| Code+File | 修改代码并运行测试 | Patch、Shell、验证 |
| Document+Memory | 查询资料并结合项目约定 | 召回、来源、隔离 |
| 多Agent | 并行调研并汇总 | 拆解、并发、合并 |
| 故障注入 | MCP断连或命令超时 | 错误处理、恢复 |
| 回滚 | 修改多文件后恢复 | Snapshot、diff、revert |

每条任务要有：输入、环境初始状态、允许工具、成功条件、关键检查点、预期 Artifact 和评分规则。

## 对比实验

### 单Agent与多Agent

比较成功率、总Token、耗时、主Context峰值和重复步骤。

### 无Memory与有Memory

比较跨轮任务正确率、错误召回率、延迟和额外成本。

### 无压缩与分层压缩

比较最大可持续轮数、关键信息保留率和摘要错误。

### JSON工具协议与原生Function Calling

比较Schema正确率、修复轮数、Provider兼容性和延迟。

### Browser DOM与视觉操作

比较元素定位成功率、动作数、Token和页面类型适用范围。

## 面试基础问题

### Agent与Workflow有什么区别

回答重点：决策路径是否预先确定、状态控制、可解释性、稳定性和适用范围。强调实际系统通常混合使用。

### ReAct解决什么问题

回答重点：让模型交替进行推理与动作，根据Observation更新下一步；工程上不需要暴露完整思维过程，关键是Action和Observation闭环。

### Function Calling和MCP有什么区别

回答重点：Function Calling 是模型输出工具调用的接口形态；MCP 是应用与外部工具/资源Server的协议。MCP Tool仍可通过Function Calling暴露给模型。

### Agent状态包含什么

回答重点：用户目标、History、计划、工具结果、环境状态、Memory、Project、预算、错误和Artifact。

### 为什么需要子Agent

回答重点：上下文隔离、角色专注和并行；同时说明协调、成本和结果验证代价。

### 短期记忆与长期记忆有什么区别

回答重点：History按时间维护当前会话；长期Memory按语义召回跨会话信息；二者的写入、失效和评估不同。

## 项目深挖问题

### 如何判断Agent任务完成

需要任务级验收条件，而不是只相信模型说完成。可以检查文件、测试、页面状态或结构化结果，模型负责总结，代码负责确定性校验。

### 如何防止无限循环

最大步骤、重复工具调用检测、总Token/时间预算、错误重试上限、状态无进展检测和人工中止。

### 如何处理工具副作用

区分只读与写操作；写操作使用幂等键、dry-run、确认、快照、补偿和审计。重试前确认上次是否部分成功。

### 如何定位Agent效果下降

按模型、Prompt、Tool Schema、环境、Memory、Project和History压缩逐层对比 Trace，不能只看最终文本。

### 多Agent为什么可能更差

错误拆解、信息丢失、结果难合并、并行冲突、总Token增加，以及父 Agent 缺少验收机制。

### Project隔离是否足够

应用层上下文隔离不等于租户安全，还需要认证授权、文件/容器/网络隔离和服务端权限检查。
