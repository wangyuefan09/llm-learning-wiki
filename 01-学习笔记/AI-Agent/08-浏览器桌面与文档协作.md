# 浏览器、桌面与文档协作

## 为什么需要多环境工具

企业任务经常跨越多个环境：从网页收集信息，在本地文件中整理，再用桌面软件检查或导出。只提供 HTTP API Tool 无法覆盖没有 API、需要登录态或必须视觉操作的应用。

多环境工具的难点不是“能点击”，而是如何维护状态、给模型提供可理解的观察、处理失败并让用户看到和介入。

## Browser

项目 Browser Plugin 使用 Playwright，按 `context_id` 管理 Runtime。能力包括：

- 打开与导航页面；
- 获取页面内容与 DOM；
- 点击、输入、上传；
- 截图与 Screencast；
- 多页面与会话状态；
- Browser Extension；
- Docker Browser 与宿主机 Connector Runtime；
- WebSocket 实时 Viewer。

### DOM与视觉

DOM 适合表单、按钮和结构化网页，定位准确、Token 可控。截图适合 Canvas、图表或视觉状态，但需要 Vision Model，成本更高。可靠 Browser Agent 应优先使用 DOM，在无法结构化理解时再使用截图。

### Browser状态

页面状态包含 URL、tab、cookie、local storage、弹窗和当前 DOM。Runtime 与聊天绑定，重置或删除 Context 时清理。Project 切换时还要检查是否允许复用登录态。

## Linux Desktop

Desktop Plugin 管理 Docker 内的 XFCE/Xpra 会话，采集：

- 显示尺寸；
- 鼠标位置；
- 活动窗口；
- 窗口列表与几何信息；
- 最新截图；
- 环境能力与错误。

Agent 通过 Desktop Skill 调用系统工具控制窗口、键鼠和应用。LibreOffice 等 GUI 软件可以在同一桌面中创建、编辑和检查文档。

### Desktop的限制

- 视觉定位比 DOM 更脆弱；
- 分辨率、主题、窗口位置会影响操作；
- 应用启动和保存可能需要等待；
- 弹窗会改变焦点；
- 截图只能说明画面，不一定说明文件已经落盘。

因此 Desktop 操作应与文件系统检查结合，不能只看界面“像是成功”。

## Code Execution

代码执行 Plugin 支持本地与 SSH 交互式 Shell：

- 维护 cwd 与会话；
- 使用 TTY/PTY 获取连续输出；
- 区分首次输出、间隔和最大超时；
- 检测 Shell Prompt 与交互式对话；
- 通过 input 工具继续发送按键；
- 支持取消与关闭 Session。

执行结果应包含退出码、标准输出、标准错误、耗时和可能生成的 Artifact。只返回文本末尾容易漏掉真正错误。

## 文件编辑与协作

Text Editor 提供 read、write、patch 等动作。Editor Plugin 再把打开文件与 Web UI Canvas 连接起来，让用户和 Agent 编辑同一个文件。

可靠文件编辑需要：

- 写前读取；
- 基于旧内容或哈希检查冲突；
- 用小 Patch 代替整文件覆盖；
- 写后重新读取或运行验证；
- 记录 diff；
- 在修改前后建立快照。

## Document Query

Document Query Plugin 可以从本地文件或 HTTP URL 获取资料，按 MIME Type 选择解析器。当前包含文本、HTML、PDF、图片、LiteParse 和 Unstructured 等路径，再围绕具体问题提取相关内容。

它与长期知识库不同：Document Query 更适合任务中临时读取一个文档；知识库适合提前摄取、长期索引和反复检索。

## 跨环境协作示例

```text
Browser打开网页并提取资料
→ Document Query读取下载的PDF
→ Agent整理结论
→ Text Editor生成Markdown或代码
→ Code Execution运行检查
→ Desktop用LibreOffice打开并检查文档
→ Time Travel保存工作区快照
→ 返回文件路径与验证结果
```

每一步都应产生可验证 Observation，而不是只让模型假设上一步成功。

## 评估方法

### Browser

- 页面到达率；
- 元素定位成功率；
- 表单完成率；
- 弹窗处理率；
- 平均动作数与恢复次数。

### Desktop

- 应用启动率；
- 窗口定位率；
- 视觉动作成功率；
- 文件实际保存率；
- 不同分辨率下稳定性。

### File/Code

- Patch应用率；
- 测试通过率；
- 并发冲突率；
- 超时/取消后进程清理率；
- Artifact路径有效率。
