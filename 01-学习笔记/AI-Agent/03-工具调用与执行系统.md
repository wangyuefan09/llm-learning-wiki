# 工具调用与执行系统

## 工具调用解决什么问题

LLM 只能生成输出，不能天然读取实时网页、运行命令或修改文件。Tool Calling 把外部能力描述成模型可选择的 Action，再把执行结果作为 Observation 送回模型。

一个工具定义通常需要：

- 唯一名称；
- 用途描述；
- 参数 Schema；
- 执行实现；
- 结果格式；
- 超时、权限和副作用说明；
- 错误类型与重试策略。

## 两种模型调用路径

### 原生Function Calling

模型 API 直接返回函数名、参数和 call id。优点是结构稳定，缺点是不同 Provider 的 Schema、响应对象和能力仍有差异。

### 文本JSON协议

Prompt 约定模型输出 JSON，应用从文本中提取并容错解析。它兼容更多模型，但更依赖模型遵循格式，也更容易把普通 JSON 误判成工具调用。

项目同时支持两条路径，并统一进入 `_execute_tool_request()`。

## 统一Tool生命周期

`helpers.tool.Tool` 定义三个阶段：

```text
before_execution
→ execute
→ after_execution
```

- `before_execution` 创建 LogItem，展示并过滤参数；
- `execute` 运行工具逻辑；
- `after_execution` 清洗返回文本、写回 History 并更新日志。

统一返回对象：

```python
Response(
    message="工具结果",
    break_loop=False,
    additional={...},
)
```

`break_loop=False` 表示把结果交给模型继续决策；`True` 表示当前工具已经形成最终回复。

## 工具发现顺序

项目执行工具时：

1. 根据当前 Agent/Project 获取 MCP 配置；
2. 尝试按工具名查找 MCP Tool；
3. 未找到时，从 Agent Profile、Project、Plugin 和内置工具路径加载 Python Tool；
4. 都未找到时使用 Unknown Tool 并把错误反馈给模型。

工具名应带稳定命名空间，否则 MCP 与本地工具同名时会产生歧义。

## 参数校验

参数校验不能完全交给 LLM。建议分三层：

- **Schema层**：类型、必填、枚举、长度；
- **业务层**：路径范围、资源是否存在、状态是否允许；
- **权限层**：调用者、Project 和工具权限。

对有副作用的工具，还应包含幂等键、dry-run 或确认参数。

## 错误处理

工具错误可以分为：

- **可修复输入错误**：参数缺失、路径错误，反馈给模型修正；
- **临时错误**：超时、限流、断连，按策略退避重试；
- **业务拒绝**：权限不足、状态冲突，不应盲目重试；
- **部分成功**：动作执行一半，需要检查副作用；
- **未知异常**：记录堆栈，向模型返回可用但不过度暴露的信息。

项目通过扩展点统一异常与错误重试，但任务级重试仍要考虑幂等性。

## 有状态工具

Browser、Desktop 和交互式 Shell 不是一次性函数：

- Browser 有 page、tab、cookie 和 DOM 状态；
- Desktop 有窗口、焦点、鼠标和应用状态；
- Shell 有 cwd、环境变量和前台进程。

有状态工具要与 `context_id`、Project 和生命周期绑定。聊天重置、删除、取消或超时后，系统需要清理运行时，避免资源泄漏或跨会话复用。

## 工具结果如何进入上下文

原始结果不应无条件完整写入 Prompt。可以分成：

- **Decision Summary**：给模型下一步决策的短文本；
- **Structured Metadata**：状态码、路径、数量、耗时；
- **Artifact**：完整日志、截图或文件保存在工作区；
- **UI Data**：仅供前端展示，不占主 Prompt。

项目已经支持把较长工具结果保存为文件并返回 include 提示，也有 History 压缩；进一步应给每类工具制定专门裁剪策略。

## 并行工具调用

独立的只读工具适合并行，例如多个资料查询。共享 Browser、同一交互 Shell 或相互依赖的写操作不适合并行。

并行系统至少要处理：

- job id；
- 启动、等待、取消；
- 并发上限和超时；
- 结果排序与归并；
- 子上下文清理；
- 父任务取消传播；
- 禁止递归并行导致任务爆炸。

## 工具测试

除了单元测试，还需要契约测试：

1. 给定合法参数，返回符合 Schema 的结果；
2. 缺参、错参能返回可修复错误；
3. 超时和取消后资源被清理；
4. 重试不会重复产生副作用；
5. 大输出不会挤爆上下文；
6. 敏感字段在日志和 History 中被遮蔽；
7. 不同 Project 的工具配置不会串用。
