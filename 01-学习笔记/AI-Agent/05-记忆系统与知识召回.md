# 记忆系统与知识召回

## Agent为什么需要记忆

模型上下文窗口只能承载当前输入，并不等于应用拥有永久记忆。Agent 长期运行时需要保存用户偏好、项目约定、历史方案和外部知识，在后续任务中按需找回。

记忆系统需要同时解决：

- 写入什么；
- 如何组织；
- 什么时候检索；
- 如何判断相关；
- 如何更新、合并和删除；
- 如何隔离不同 Project；
- 如何避免错误和陈旧信息污染决策。

## 四类信息

| 信息 | 主要用途 | 推荐载体 |
| --- | --- | --- |
| 当前任务消息与工具结果 | 保证本轮连续性 | History |
| 稳定偏好与项目约定 | 跨聊天复用 | Long-term Memory |
| 已验证问题解决方案 | 复用排障经验 | Solutions Memory |
| 文档、手册和资料 | 外部事实与证据 | Imported Knowledge / RAG |

不要把所有 History 都永久写入 Memory。大量临时尝试和失败猜测会降低未来召回质量。

## 项目当前存储

Memory 使用 LangChain FAISS，索引向量为余弦相似度，Embedding 带本地缓存。数据区域包括：

- `main`：长期稳定记忆；
- `fragments`：对话中提取的记忆片段；
- `solutions`：历史解决方案；
- imported knowledge：外部知识文档。

FAISS 索引与 docstore 持久化到本地，并记录 Embedding Provider/Model。模型配置变化时重建向量；`index.faiss.sha256` 用于检查索引文件完整性。

## 记忆召回流程

```text
当前用户消息 + 部分History
→ 可选：Utility Model生成检索Query
→ 分别召回memory/fragments与solutions
→ 相似度阈值与数量上限
→ 可选：Utility Model做相关性后过滤
→ 把保留结果注入Extras
→ 主模型基于记忆继续决策
```

项目允许按间隔触发召回，而不是每轮都检索。检索 Query、结果和数量会写入日志，便于定位“没有召回”还是“召回后没使用”。

## 记忆写入

项目在 `monologue_end` 扩展中支持从任务历史提取 fragments 和 solutions，也提供显式 `memory_save` 工具。写入前可以通过 Consolidator 对相似记忆做：

- keep separate：保留为独立条目；
- merge：合并；
- replace：替换旧条目；
- update：更新已有条目。

这比无条件追加更能控制重复，但模型对合并关系的判断也需要评估。

## Project记忆隔离

默认启用 `project_memory_isolation` 时，当前 Project 的索引位于：

```text
usr/projects/<project>/.a0proj/memory
```

全局或自定义记忆位于 `usr/memory/`。项目知识位于 `.a0proj/knowledge`。这种设计降低跨项目召回，但仍应测试 Project 切换、缓存和后台任务是否使用了正确作用域。

## Memory与RAG的关系

两者都可以用 Embedding 检索，但数据来源和治理方式不同：

- Memory 更偏向 Agent 运行中形成的偏好、经验和状态；
- RAG Knowledge 更偏向外部文档事实，强调来源、切分、权限和引用；
- Memory 常被自动写入，错误污染风险更高；
- Knowledge 通常有更明确的数据摄取和更新流程。

项目当前把 Memory 与 imported knowledge 放在同一 FAISS 体系中，通过 metadata/area 区分。业务规模扩大后可以拆分索引和治理流程。

## 召回质量问题

### 没召回

可能原因：Query 生成偏离、Embedding 不适配、阈值过高、Project 作用域错误或索引未更新。

### 召回错误

可能原因：记忆本身过于宽泛、相似词误匹配、阈值过低、缺少时间和来源过滤。

### 召回正确但未使用

可能原因：记忆在 Prompt 中位置太弱、与当前指令冲突、上下文噪声太大。

### 使用了陈旧记忆

需要记忆时间、版本、失效条件和人工整理入口。

## 评估方法

建立记忆查询集，每条包含：

- 当前问题；
- 应召回 Memory ID；
- 不应召回的相似记忆；
- 是否应使用全局或项目记忆；
- 正确回答或动作。

指标包括 Recall@K、Precision@K、MRR、错误项目召回率、陈旧记忆使用率、后过滤保留率、召回延迟和额外 Token。

## 个人理解

长期记忆的难点不在向量检索，而在写入治理。错误信息一旦被包装成“记忆”，会在未来多次参与决策。一个可靠 Memory 系统必须支持来源、作用域、时间、编辑、删除和评估。
