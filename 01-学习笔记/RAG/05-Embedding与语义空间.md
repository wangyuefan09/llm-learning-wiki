# Embedding与语义空间

## Embedding是什么

Embedding把文本、图片等对象编码成固定维度的稠密数值向量。一个输出维度为 1024 的文本 Embedding 模型，无论输入是短句还是较长段落，都会返回 1024 个数值。

这些数值不是可直接阅读的标签，而是模型从训练数据中学到的表示。语义相近的文本通常在向量空间中更接近，但实际效果仍取决于模型、语言、领域和输入方式。

## 相似度计算

### 余弦相似度

比较两个向量方向的夹角。值越大，方向越接近。

### 内积

把对应维度乘积后求和。两个向量完成 L2 归一化后，内积等于余弦相似度。

### 欧式距离

计算向量之间的直线距离。距离越小表示越接近。

索引使用哪种距离，需要与模型训练方式和向量数据库配置保持一致。

## 向量归一化

L2 归一化把向量缩放为模长 1 的单位向量，不改变方向。归一化后，比较结果不再受原始向量长度影响，并且内积可以直接表示余弦相似度。

是否应在应用侧归一化取决于 Embedding 模型和向量数据库的约定，不能重复或盲目处理。

## 文本表示方法的演进

### 静态词向量

Word2Vec、GloVe 为每个词提供固定向量，因此难以区分同一个词在不同上下文中的含义。

### 上下文表示

BERT 等模型会根据上下文生成词或句子的表示。Cross-Encoder 把 query 和候选文本一起编码，相关性判断准确但无法提前独立计算所有候选向量，不适合直接做大规模第一阶段召回。

### 双塔与句向量

Sentence-BERT、SimCSE、BGE 等模型可以独立编码 query 和文档，文档向量能够预先写入索引。在线阶段只计算 query 向量并执行近邻搜索，因此适合 RAG 召回。

这不是严格的“三代算法标准”，而是便于理解检索表示方法的分类。

## Embedding在RAG中的作用

离线阶段：

1. 对文档 chunk 编码；
2. 将向量、原文和元数据写入索引。

在线阶段：

1. 对 query 编码；
2. 在同一个兼容空间中搜索近邻；
3. 返回最相关的候选 chunk。

Embedding 决定语义召回的能力上限，但检索质量还受 chunk、索引、过滤和查询表达影响。

## 常见模型

- OpenAI `text-embedding-3-large`；
- 通义系列文本向量模型；
- BAAI BGE 系列，如 `bge-m3`；
- Qwen3 Embedding 系列；
- Jina Embeddings 系列。

模型名称、维度和最大输入长度会随版本变化，使用时应记录准确版本和官方说明。

## 维度是否越高越好

不是。更高维度可能提高表示容量，也会增加：

- 向量存储空间；
- 索引内存；
- 距离计算量；
- 网络传输和重建索引成本。

最终应根据业务评估集比较召回质量、延迟和成本，而不是只看维度。

## 长输入模型是否可以不切文档

长输入只表示模型能够接受更长文本，不代表整篇文档适合压缩成一个检索向量。长文本可能包含多个主题，单个向量会平均化局部信号，也无法精确定位支撑答案的证据。

合理做法是根据语义边界和目标问题选择 chunk 粒度，并在需要完整上下文时使用父子块或命中后扩展。

## query和文档是否必须使用同一模型

两者必须处于兼容的向量空间。最常见做法是使用同一个模型和版本，并按模型要求分别提供 query/document 指令。

部分非对称检索模型会使用分别训练但相互兼容的 query encoder 和 document encoder。此时编码器可以不同，但它们必须是同一套训练体系，不能任意混搭两个无关模型。

## 项目当前配置

项目当前支持：

- provider：Jina 或 OpenAI-compatible；
- 模型：由运行配置提供，不在业务代码中写死；
- 示例向量维度：1024；
- 距离类型：默认余弦相似度。

Embedding 模型名称、接口地址和维度都是配置项。示例值只是可运行结构，不代表某个模型已经在目标风电数据上胜出，也不能据此判断模型是本地还是远程部署。

## 如何评估模型是否合适

- 同一故障的不同表达能否互相召回；
- 对设备名称、故障码、部件号和检修动作是否敏感；
- 精确术语和自然语言表达能否兼顾；
- Recall@K、MRR 和 nDCG 是否优于基线；
- 编码延迟、吞吐、显存或接口成本是否可接受。

## 更换Embedding模型的影响

1. 检查输出维度和距离类型；
2. 同步更新 OpenSearch mapping；
3. 对全部历史 chunk 重新生成向量；
4. 建立新索引并完成回放评估；
5. 验证后切换别名或读流量；
6. 保留回滚能力。

更换模型是一次完整的索引迁移，不是只修改模型名称。
