# RAG知识增强与面试问题清单

## 当前判断

项目已经实现风电知识库的核心链路，包括人工上传、中文切分、表格检索、业务 metadata、权限过滤基础、文档状态机、reindex、可恢复删除、Agent 工作流和 Langfuse 观测。

当前项目的核心链路已经实现，下一阶段需要补齐：

- 缺少真实风电数据上的效果评估；
- 缺少真实服务端到端运行证据；
- 缺少认证、后台任务、迁移和对象存储等工程能力；
- 缺少性能、容量和故障演练数据。

面试准备的重点不再是继续增加概念，而是把每项选择落实为源码、实验、指标和取舍。

## 当前面试冲刺优先级

当前最需要强化的是 RAG 评估，优先掌握理论、问题定位和面试追问，不以立即完成整套评估开发为前置条件。

1. [[09-2-RAG检索评估指标|RAG检索评估指标]]：掌握 Hit Rate、Recall、Precision、MRR 和 nDCG；
2. [[09-3-RAG生成与引用评估|RAG生成与引用评估]]：掌握 Faithfulness、Relevance、Correctness、完整性、引用和拒答；
3. [[09-4-Agentic RAG评估|Agentic RAG评估]]：掌握守卫、Query Rewrite、证据评分、循环和成本评估；
4. [[09-1-RAG评估集与实验设计|RAG评估集与实验设计]]：掌握标注、基线、单变量和分组实验；
5. [[09-5-RAG问题定位与评估面试问答|RAG问题定位与评估面试问答]]：完成脱稿回答和问题定位自测。

### 2. 技术选型与取舍

#### 文档解析

- 为什么选择 Docling？

- 如何评估解析质量？

#### 文本切分

- 为什么是当前 chunk_size 和 overlap？
- 启发式长度与模型 Token 有什么区别？
- 为什么 section-aware 更适合当前文档？
- 为什么只保留递归切分内核？
- 为什么没有使用父子检索？

#### Embedding

- 如何选择模型和输出维度？
- query 和文档如何保持同一向量空间？
- 是否需要归一化？
- 当前是本地服务还是兼容 API？
- 换模型后如何迁移？

#### OpenSearch

- 为什么没有选择 pgvector 或 Milvus？
- HNSW 的 m、ef_construction、ef_search 是什么？
- metadata 和权限 filter 如何影响 ANN？
- Mapping 不兼容为什么不自动删除索引？
- RRF 为什么不需要分数归一化？

### 3. 一致性和故障恢复

- 数据库成功、OpenSearch 失败怎样补偿？
- 为什么用 token 而不只看 status？
- 租约过期后如何安全接管？
- 旧任务恢复执行时怎样避免覆盖新任务？
- reindex 切换后旧版本清理失败怎么办？
- 删除到一半进程退出怎么办？

### 4. 真实效果

- 优化前后的指标分别是多少？
- 测试集怎样构建？
- 最难的问题类型是什么？
- 有哪些失败案例？
- 检索、评分和生成分别耗时多少？
- 端到端 P95 是多少？
- 一次请求的 Token 和成本是多少？
