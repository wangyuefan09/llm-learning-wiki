# RAG与微调

## 核心区别

RAG在推理时查询外部知识，微调通过训练改变模型参数。两者解决的问题不同，可以组合使用。

| 对比项 | RAG | 微调 |
| --- | --- | --- |
| 知识位置 | 外部知识库 | 模型参数及训练形成的行为模式 |
| 更新时间 | 更新索引即可 | 通常需要准备数据并再次训练 |
| 可追溯性 | 可以返回引用和原文 | 很难从参数中追溯具体来源 |
| 主要依赖 | 解析、切分、检索和上下文组织 | 数据质量、训练方法与模型能力 |
| 运行成本 | 检索、重排和额外上下文 Token | 微调后推理链路相对直接 |
| 适合目标 | 最新知识、私有知识、证据问答 | 风格、格式、任务行为和能力适配 |

## RAG的优势和限制

优势：

- 知识可以独立更新；
- 可以接入私有文档；
- 回答能够附带来源；
- 不必重新训练基础模型。

限制：

- 最终效果依赖解析、chunk、召回和排序；
- 上下文窗口和 Token 预算有限；
- 检索结果错误时，生成结果也会受影响；
- 系统链路比单次模型调用更复杂。

## 微调的优势和限制

优势：

- 可以让输出风格、格式和任务行为更稳定；
- 推理时不需要为这些行为提供大量示例；
- 适合强化特定任务的执行方式。

限制：

- 训练和评估需要成本；
- 数据变化后可能需要重新训练；
- 不适合频繁更新事实知识；
- 不能天然提供事实来源。

固定 JSON 或 SQL 输出不一定必须微调。提示词、结构化输出和约束解码通常应先作为基线；只有基线无法满足稳定性或成本要求时，再评估微调。

## 组合使用

### 客服系统

微调负责服务语气、意图分类和流程习惯，RAG提供最新产品信息、政策和订单规则。

### 医疗知识助手

模型训练负责术语和任务表达，RAG提供可更新、可引用的指南和研究资料。涉及事实判断时仍需专业审核。

### 企业知识问答

微调或提示词让模型遵循企业回答格式，RAG负责检索内部制度、手册和故障案例。

## 选择方法

先判断目标：

- 需要更新知识和提供证据：优先RAG；
- 需要稳定行为、风格或任务格式：评估提示词、结构化输出和微调；
- 两类需求同时存在：组合使用，并分别评估检索质量和生成质量。
