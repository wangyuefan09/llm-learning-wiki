# RAG检索评估指标

## 评估前先确定口径

指标必须先说明评估粒度：

- 文档级：只要找到包含答案的文档即为相关；
- chunk 级：必须找到具体支撑答案的切片；
- 二元相关性：相关或不相关；
- 分级相关性：完全相关、部分相关、弱相关、不相关。

同一批结果在文档级和 chunk 级可能得到不同评价，因此面试时不只说“Recall@5”，还要说标注对象和计算口径。

## Hit Rate@K

前 K 个结果中是否至少存在一个相关结果。

```text
Hit@K(q) = 1，Top-K存在相关结果
Hit@K(q) = 0，Top-K不存在相关结果

Hit Rate@K = 所有问题Hit@K的平均值
```

适用场景：只要找到一个核心证据就能回答。

局限：不关心第一个正确结果排在哪里，也不关心是否漏掉其他相关证据。

## Recall@K

衡量 Top-K 覆盖了多少已标注相关结果。

```text
Recall@K(q) = Top-K中相关结果数 / 该问题全部相关结果数
```

例如，某个问题共有 4 个相关 chunk，Top-5 找到了 3 个：

```text
Recall@5 = 3 / 4 = 0.75
```

适用场景：回答需要多条证据或需要覆盖多个步骤。

注意：

- 如果每题只标注了一个相关结果，Recall@K 与 Hit Rate@K 在数值上可能相同；
- 如果标注并不完整，系统找到的其他正确证据可能被误算为无关；
- 跨版本比较时必须使用同一份标注集。

## Precision@K

衡量 Top-K 中相关结果的比例。

```text
Precision@K(q) = Top-K中相关结果数 / K
```

例如 Top-5 中有 3 个相关结果：

```text
Precision@5 = 3 / 5 = 0.6
```

适用场景：上下文窗口有限，需要减少噪声和无效 Token。

口径约定：当检索器实际返回少于 K 条时，分母使用 K 还是实际返回数必须在评估配置中固定。

## MRR

MRR 关心第一个相关结果的排名。

```text
RR(q) = 1 / 第一个相关结果的排名
MRR = 所有问题RR的平均值
```

如果三个问题的第一个相关结果分别排在第 1、2、4 位：

```text
MRR = (1 + 1/2 + 1/4) / 3 ≈ 0.583
```

优点：能衡量核心证据是否靠前。

局限：只关注第一个相关结果，不关心后续相关证据。

## nDCG@K

nDCG 同时考虑结果的相关程度和排名位置，适合分级相关性。

```text
DCG@K = Σ (2^rel_i - 1) / log2(i + 1)
nDCG@K = DCG@K / IDCG@K
```

- `rel_i` 是第 i 个结果的相关性等级；
- `IDCG` 是理想排序下的 DCG；
- nDCG 越接近 1，说明高相关结果越靠前。

当同一问题存在“直接支撑答案”“提供背景”“弱相关”等等级时，nDCG 比只看首个结果的 MRR 更合适。

## 指标选择

| 想回答的问题 | 优先指标 |
| --- | --- |
| Top-K 中有没有任何正确证据 | Hit Rate@K |
| 是否覆盖全部必要证据 | Recall@K |
| 返回内容中的噪声是否过多 | Precision@K |
| 第一个核心证据是否足够靠前 | MRR |
| 不同相关程度的结果是否排序合理 | nDCG@K |

项目中不应只选一个指标。常见组合是：

```text
Recall@K + MRR + nDCG@K + 检索延迟
```

## 如何解读指标冲突

### Recall上升、Precision下降

可能是 Top-K 或候选范围增大，找回了更多证据，也带来了更多噪声。需要继续查看生成质量和 Token 代价。

### Hit Rate高、MRR低

说明大部分问题最终能找到证据，但正确证据排名靠后。可以检查融合、重排和精确字段权重。

### 整体指标上升、某一类问题下降

说明方案对不同 query 类型的收益不一致。必须按故障码、自然语言、表格和无答案问题分组分析。

## 定位检索失败

| 现象 | 更可能的原因 |
| --- | --- |
| 原文有答案，解析结果没有 | 文档解析问题 |
| 正确内容被切散 | chunk 边界或粒度问题 |
| 同义表达持续召回不到 | Embedding 领域适配问题 |
| 故障码被语义相似结果压住 | BM25、keyword、字段权重或融合问题 |
| 存在正确证据但完全没有候选 | metadata、权限、状态或版本过滤问题 |
| BM25和向量各自正常，融合后排名变差 | RRF 候选范围或融合配置问题 |

## 面试回答

> 我不会只用一个 Recall@5 评价检索。Hit Rate@K 回答 Top-K 里有没有证据，Recall@K 回答覆盖了多少已标注证据，MRR 关注第一个核心证据的排名，nDCG 适合存在多级相关性的场景。实际比较 BM25、向量和 RRF 时，我会同时看 Recall、MRR、nDCG、延迟和不同问题类型的分组结果。
