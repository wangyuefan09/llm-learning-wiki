# RAG评估集与实验设计

## 为什么先做评估集

没有固定评估集时，很容易出现以下问题：

- 每次使用不同问题测试，版本之间不可比；
- 只挑选表现好的样例，无法看见回归；
- 答案错误时，不知道是检索还是生成问题；
- 调整 chunk、Embedding、Top-K 和 Prompt 后，无法证明改动是否有效。

评估集是所有离线指标和回归实验的共同基础。

## 一条样本需要什么字段

```json
{
  "question_id": "QUESTION_ID",
  "question": "齿轮箱出现GBX-017告警时如何排查？",
  "question_type": "故障码",
  "relevant_doc_ids": ["DOC_ID"],
  "relevant_chunk_ids": ["CHUNK_ID"],
  "reference_answer": "REFERENCE_ANSWER",
  "answerable": true,
  "expected_filters": {
    "component": "齿轮箱",
    "fault_code": "GBX-017"
  },
  "relevance_grades": {
    "CHUNK_ID": 3
  },
  "difficulty": "medium"
}
```

字段用途：

- `question` 用于执行检索和问答；
- `relevant_doc_ids` 用于文档级评估；
- `relevant_chunk_ids` 用于 chunk 级评估；
- `reference_answer` 用于答案正确性和完整性评估；
- `answerable` 用于无答案和拒答评估；
- `expected_filters` 用于验证业务字段过滤；
- `relevance_grades` 用于 nDCG 等分级相关性指标；
- `question_type` 和 `difficulty` 用于分组分析。

## 风电问题集覆盖面

| 类型 | 目的 | 主要检查对象 |
| --- | --- | --- |
| 故障码查询 | 验证精确术语命中 | BM25、keyword、metadata filter |
| 风机型号和部件 | 验证业务字段过滤 | Mapping 和 filter |
| 自然语言故障描述 | 验证语义召回 | Embedding 和向量检索 |
| 同义改写 | 验证表达变化的稳定性 | Embedding、Query Rewrite |
| 表格问题 | 验证行列语义和结构回查 | TableChunker、表格存储 |
| 多证据问题 | 验证相关证据覆盖 | Recall@K、上下文组织 |
| 模糊问题 | 验证澄清和兜底 | Agent 路由、拒答 |
| 无答案问题 | 验证幻觉控制 | 证据不足兜底 |
| 超出风电领域 | 验证守卫节点 | guardrail |

## 标注层级

### 文档级标注

标注“答案来自哪些文档”。成本较低，适合先建立基线，但不能精确评估 chunk 排名。

### Chunk级标注

标注具体支撑证据。适合 Recall@K、MRR 和 nDCG@K，但要注意切分参数或索引版本改变后，`chunk_id` 可能需要重新标注。

### 参考答案和要点标注

除了完整参考答案，还可以拆成必须覆盖的要点，便于评估答案完整性，避免对表达方式过度敏感。

## 建立基线

项目适合按以下顺序比较：

1. BM25；
2. 纯向量检索；
3. BM25 + HNSW + RRF；
4. RRF + Query Rewrite；
5. RRF + 可选 Cross-Encoder Reranker。

基线实验必须固定：

- 评估集版本；
- 文档集和索引版本；
- chunk 配置；
- Embedding 模型和维度；
- Top-K 和 filter；
- Prompt 和 LLM 版本；
- 随机性配置。

## 单变量实验

一次只修改一个核心变量。

错误方式：

```text
同时更换 Embedding、chunk_size、Top-K 和 Prompt
```

正确方式：

```text
固定数据集、Embedding、Top-K 和 Prompt
只比较不同 chunk_size
```

如果改变 chunk 或 Embedding 模型，需要重建索引，不能把新 query 向量与旧文档向量直接比较。

## 分组评估

整体平均分可能掩盖局部回归。例如混合检索整体 Recall@5 上升，但故障码查询可能下降。

至少按以下维度分组：

- 问题类型；
- 难度；
- 文档格式；
- 正文或表格；
- 有答案或无答案；
- 是否需要 metadata filter；
- 是否触发 Query Rewrite。

## 版本记录

每次评估至少保存：

```text
评估集版本
代码版本
文档集与索引版本
Embedding模型与维度
chunk_size / overlap / Top-K
RRF或Reranker配置
Prompt与LLM版本
整体指标
分组指标
失败样本
```
