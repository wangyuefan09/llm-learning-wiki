# Agentic RAG评估

## 为什么不能只评最终答案

固定 RAG 通常按预设链路执行，Agentic RAG 还会做范围判断、工具调用、证据评分、查询改写和循环决策。

两个 Agent 可能最终给出同样的正确答案，但其中一个只检索一次，另一个循环多次且消耗大量 Token。只评答案会忽略执行路径和成本。

Agentic RAG 评估需要同时回答：

```text
最终答案是否更好？
路由和工具决策是否正确？
质量收益是否值得额外延迟和Token？
```

## 守卫节点评估

守卫节点本质上是一个二分类器，评估集需要包含风电问题和非风电问题。

| 真实类别 | 守卫结果 | 评价 |
| --- | --- | --- |
| 风电问题 | 通过 | 正确通过 |
| 风电问题 | 拦截 | 误拦截 |
| 非风电问题 | 拦截 | 正确拦截 |
| 非风电问题 | 通过 | 漏放 |

可计算：

- 风电问题通过率；
- 非风电问题拦截率；
- 误拦截率；
- 漏放率；
- 不同守卫阈值下的取舍。

## Query Rewrite评估

改写不能只评价语句是否更专业，而要比较它对检索结果的实际影响。

对每个触发改写的问题记录：

```text
原始query
改写query
改写前Recall@K / MRR
改写后Recall@K / MRR
正确证据排名变化
改写耗时
改写Token
是否偏离原始意图
```

一个可用的指标是：

```text
Rewrite Success Rate
= 改写后检索指标实际提升的问题数
  / 全部触发改写的问题数
```

还要统计负收益：

- 改写后正确证据排名下降；
- 具体故障码被改成泛化描述；
- 新 query 引入了用户没有提到的设备或故障；
- 指标没有变化，但增加了延迟和 Token。

## 文档评分节点评估

`grade_documents` 属于证据过滤和路由节点，不等同于专用 Cross-Encoder Reranker。

对已标注候选证据建立混淆矩阵：

| 真实相关性 | 评分节点 | 结果 |
| --- | --- | --- |
| 相关 | 保留 | 正确保留 |
| 相关 | 删除 | 正确证据误删 |
| 不相关 | 删除 | 正确过滤 |
| 不相关 | 保留 | 噪声漏放 |

最需要关注“正确证据误删率”。证据被删除后，生成节点无法恢复该信息。

还可以比较：

- 评分前后 Precision@K 的变化；
- 评分前后 Recall@K 的变化；
- 每条证据评分的延迟和 Token；
- 专用 Reranker 与 LLM 评分的质量成本对比。

## 工具调用和检索评估

需要记录：

- 应该检索时是否真正发起检索；
- 工具参数是否保留 query 和 metadata filter；
- 是否正确使用混合检索或 BM25 回退；
- 基础设施失败是否被识别为错误，而不是正常零结果；
- 返回的 source 是否对应实际候选证据。

## 循环和兜底评估

记录：

- 平均检索次数；
- 检索次数 P95；
- Query Rewrite 触发率；
- 达到最大检索次数的比例；
- 证据不足兜底率；
- 循环超时或异常结束率；
- 兜底问题中的正确兜底和错误拒答。

只限制最大检索次数能避免无限循环，但不代表每次循环都有价值。

## 固定RAG与Agentic RAG对比

| 维度 | 固定RAG | Agentic RAG |
| --- | --- | --- |
| 检索质量 | 基线 Recall/MRR | 改写和评分后是否提升 |
| 答案质量 | 基线生成指标 | 是否减少无证据回答 |
| 路由 | 固定链路 | 守卫、改写和兜底决策 |
| 延迟 | 通常较低 | 多次 LLM 和检索调用 |
| 成本 | 调用次数较少 | 需要统计额外 Token 和调用次数 |

最终判断不是“Agent 指标更高”，而是：

```text
质量增益
是否足以支付
额外延迟 + Token + 系统复杂度
```

## 项目当前可记录数据

当前代码已经返回或记录：

- `retrieval_attempts`；
- `rewritten_query`；
- `reasoning_steps`；
- `sources_count`；
- `chunks_used`；
- `search_mode`；
- `execution_time`；
- `trace_id`；
- 守卫、检索、评分、改写和生成的节点观测。

这些字段提供了评估数据基础，但当前尚未形成固定评估集和固定指标报告。

## 面试回答

> Agentic RAG 不能只评最终答案。我会分别评估守卫节点的误拦截和漏放、Query Rewrite 前后的 Recall 和 MRR 变化、文档评分对正确证据的误删率、平均检索次数和兜底率。然后把 Agentic RAG 与固定 RAG 在答案质量、P95 延迟、Token 和模型调用次数上对比，判断额外复杂度是否带来了足够净收益。
