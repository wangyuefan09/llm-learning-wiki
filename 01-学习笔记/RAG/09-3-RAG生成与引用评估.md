# RAG生成与引用评估

## 检索正确不等于答案正确

生成阶段可能出现：

- 忽略已经召回的正确证据；
- 对证据做过度推断；
- 混合多个片段后生成了原文不存在的因果关系；
- 回答了相关背景，但没有直接回应问题；
- 只覆盖参考答案的部分要点；
- 引用了看似相关、实际不支持结论的来源。

因此，生成评估需要拆开“是否忠于证据”“是否答非所问”“答案本身是否正确”“是否完整”。

## Faithfulness

Faithfulness 检查回答中的可验证结论是否得到当前检索上下文支持。

可以按结论粒度评估：

```text
将答案拆成独立可验证结论
→ 逐条判断是否被检索证据支持
→ 计算受支持结论比例
```

例如，上下文只说：

```text
齿轮箱振动异常可能与轴承磨损有关。
```

答案却说：

```text
该故障一定由轴承磨损导致。
```

主题相关不代表忠于证据，这条结论把可能性改成了确定性。

## Answer Relevance

Answer Relevance 检查答案是否直接响应用户意图。

例如用户问“应该按什么顺序排查”，回答只介绍故障定义和设备背景。内容可能正确，但与“排查顺序”不匹配。

评估时可以检查：

- 是否回答了用户要求的任务类型；
- 是否存在大量无关背景；
- 是否漏掉问题中的关键限定条件；
- 是否处理了问题的全部子问题。

## Answer Correctness

Correctness 判断答案与参考答案或专家事实是否一致。

Faithfulness 和 Correctness 不是同一个问题：

| 情况 | Faithfulness | Correctness |
| --- | --- | --- |
| 忠实复述了一段错误资料 | 可能高 | 低 |
| 凭模型记忆给出了正确信息，但检索证据不支持 | 低 | 可能高 |
| 证据和答案都正确 | 高 | 高 |
| 无根据且事实错误 | 低 | 低 |

在企业知识库中，通常希望答案同时具有较高 Faithfulness 和 Correctness。

## Completeness

Completeness 判断参考答案的关键要点被覆盖了多少。

可以将参考答案拆成要点：

```text
要点1：检查设备型号和当前工况
要点2：核对故障码和告警时间
要点3：检查振动、温度等趋势
要点4：按SOP执行进一步排查
```

根据答案覆盖的要点数计算完整性。这比对整段文本做字面匹配更适合开放式回答。

## Context Precision和Context Recall

这类指标位于检索和生成之间：

- Context Precision 关心提供给 LLM 的上下文中是否充斥无关噪声；
- Context Recall 关心提供的上下文是否覆盖参考答案所需证据。

Ragas 等工具的具体指标定义可能随版本和是否提供 reference 而变化，实际使用时要固定工具版本、评估模型和指标配置。

## 引用评估

引用评估应拆成两个维度。

### 引用正确性

被引用的文档或 chunk 是否真正支持对应结论。

```text
引用正确率 = 能支持结论的引用数 / 全部引用数
```

### 引用覆盖率

答案中需要证据支持的重要结论是否都有引用。

```text
引用覆盖率 = 有引用支持的重要结论数 / 全部重要结论数
```

引用存在不代表引用正确，只检查是否返回 `source` 字段是不够的。

## 无答案和拒答评估

评估集必须同时包含有答案和无答案问题。

| 真实情况 | 系统行为 | 结果 |
| --- | --- | --- |
| 有证据 | 正常回答 | 正确回答 |
| 有证据 | 证据不足兜底 | 错误拒答 |
| 无证据 | 请求补充信息或拒答 | 正确兜底 |
| 无证据 | 强行给出具体结论 | 误答或幻觉 |

关键指标：

- 无答案误答率；
- 有答案错误拒答率；
- 兜底信息是否能指导用户补充设备型号、部件、故障码和工况。

## LLM-as-a-Judge

当无法用字符串规则评估开放式答案时，可以使用 LLM 作为评估器，但不应把它当成绝对真值。

主要风险：

- 评估模型对答案长度、表达风格和顺序存在偏好；
- 同一模型生成和评分可能存在自我偏好；
- 专业领域知识不足时可能误判；
- Prompt、温度和模型版本变化会导致分数漂移；
- 一个总分不易解释具体失败原因。

降低风险的方法：

1. 使用明确评分规则和结构化输出；
2. 固定评估模型、版本和推理配置；
3. 用人工标注的小型集合先校准 Judge；
4. 对高风险、低置信和版本分歧样本人工复核；
5. 保留评分理由，不只保留数字。

## 三种评估方式如何组合

```text
确定性规则和检索指标
+ LLM自动评分
+ 人工抽样复核
```

- 确定性指标用于检索排名、延迟、Token 和结构化字段；
- LLM Judge 用于忠实性、相关性和完整性的批量评估；
- 人工复核用于专业术语、复杂表格、故障排查步骤和 Judge 争议样本。

## 面试回答

> 生成评估不能只看答案语义相似度。我会分别看 Faithfulness、Answer Relevance、Correctness 和 Completeness。Faithfulness 判断结论是否受检索证据支持，Correctness 判断是否符合参考事实，两者不能混为一谈。另外还要评估引用正确率、引用覆盖率和无答案问题的误答率。自动评估会与人工抽样结合，避免把 LLM Judge 的分数直接当成真值。
