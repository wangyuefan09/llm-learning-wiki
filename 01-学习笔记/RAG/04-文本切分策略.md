# 文本切分策略

## 为什么需要切分

切分的目标是让每个 chunk 足够聚焦，便于召回，同时保留回答问题所需的上下文。切得太小会丢失指代和因果关系，切得太大会混入多个主题并稀释检索信号。

长输入 Embedding 模型没有消除切分需求。把整篇长文压成一个向量会降低证据定位粒度，也会增加嵌入和生成阶段的计算量。

## 常见策略

### 固定大小与滑动窗口

按字符、词或 Token 控制块大小，并通过 overlap 缓解边界截断。优势是行为可预测，缺点是可能切断句子或语义单元。

### 按段落或标题切分

TXT 可以按空行切，Markdown 可以按标题层级切。结构清晰时，这类边界比固定长度更符合原文语义。

### 递归切分

按照段落、换行、句末标点、空格等分隔符逐级尝试，只有上一级单元过长时才继续拆分。它比直接硬切更容易保留原文结构。

### 语义切分

根据相邻句子的 Embedding 变化寻找语义边界。边界可能更自然，但索引构建更慢，阈值也需要用目标数据评估。

### 父子分块

使用小块检索，再返回对应的大块给 LLM。它缓解了检索精度与上下文完整性的矛盾，但需要维护 child 到 parent 的映射和额外存储。当前 `agentic-rag` 没有实现父子检索器。

## chunk_size和overlap

- `chunk_size` 控制单个 chunk 的目标最大长度；
- `overlap` 控制相邻 chunk 的重复长度；
- 参数必须注明单位，字符、词、启发式长度和模型 Token 不能混用；
- overlap 太小可能丢失边界上下文，太大会增加重复索引、存储和召回冗余。

## 项目当前实现

项目使用 `TextChunker` 完成 section-aware 外层编排：

1. 规范化非空 sections；
2. 优先把 section 作为语义边界；
3. 连续合并过短 section；
4. 对长 section 调用递归切分；
5. section 不可用时回退到 `raw_text`；
6. 在每个切片前补充文档标题和章节标题；
7. 使用字符硬上限处理无分隔符的异常长文本。

底层当前只支持：

```text
LangChain RecursiveCharacterTextSplitter
```

分隔符顺序包括：

```python
["\n\n", "\n", "。", "？", "！", "；", ".", " ", ""]
```

## 当前长度计算

默认参数：

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `chunk_size` | 800 | 启发式长度预算 |
| `overlap_size` | 100 | 与长度函数相同的估算单位 |
| `min_chunk_size` | 120 | 小 section 合并阈值 |
| `max_chunk_chars` | 6000 | 独立字符硬上限 |

默认 `estimate_tokens()` 并不是严格 tokenizer：

- 中文字符和中文/全角标点按单元计数；
- 英文、数字以及带连接符的技术词按词计数；
- 其他非空字符按近似比例折算。

准确表述是“中文友好的启发式 Token 估算”，而不是“按照 Embedding 模型精确计算 800 Token”。构造 `TextChunker` 时可以注入其他 `length_function`，但当前工厂默认仍使用启发式估算。

源码位置：

- `src/services/chunk/text_chunker.py`
- `src/services/chunk/table_chunker.py`
- `src/services/chunk/factory.py`

## 表格切分

表格不直接把二维 JSON 送去 Embedding。`TableChunker` 会：

1. 重复文档标题、表题和表头；
2. 把行展开为“列名=值”的文本；
3. 按长度把数据行分组；
4. 记录 `table_id`、`row_start` 和 `row_end`；
5. 生成 `chunk_type=table` 的独立切片。

这样可以用语义文本召回，同时保留行范围用于回查原始结构。

## 如何结合Embedding模型确定参数

1. 确认 Embedding 模型的最大输入长度和 query/document 编码要求。
2. 统计真实文档 section 和 Token 长度分布。
3. 用目标模型 tokenizer 复核启发式估算误差。
4. 建立带相关 chunk 标注的问题集。
5. 对多组 chunk_size、overlap 构建索引。
6. 比较 Recall@K、MRR、nDCG、延迟、索引体积和上下文完整性。
7. 按文档类型分析结果，不寻找脱离数据的通用最佳值。

## chunk质量评估

### 结构统计

- 每篇文档 chunk 数量的均值、中位数、P90 和最大值；
- chunk 长度 P50/P90/P99；
- 极短和极长 chunk 占比；
- section-aware 与 raw_text fallback 比例；
- 表格切片数量和平均行数；
- 空 chunk 和异常文档比例。

### 内容抽样

- 一个 chunk 能否表达相对完整的主题；
- 标题、章节与正文是否匹配；
- 是否包含页眉页脚或解析噪声；
- 关键上下文是否被切散；
- 表格切片是否重复表头并保留有效行范围；
- 命中 chunk 是否足够支持答案。

### 当前项目状态

中文切分、短 section 合并、字符硬上限和表格切分已有单元测试，但还没有真实风电文档的分布统计和参数对比报告。因此源码能力可以描述为已实现，参数效果仍应描述为待验证。
